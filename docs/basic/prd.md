# 产品逻辑说明

## 问题与目标

目标用户是在 Obsidian 中写作并发布到微信公众号、飞书云文档和其他内容平台的创作者。项目要解决的是 Markdown 内容从本地知识库到发布端时的排版失真、图片/公式/表格兼容、重复复制上传、多平台分发和草稿管理成本。成功标准是用户能在 Obsidian 中完成预览、复制、同步和分发，并对最终发布效果有足够信心。

## 用户故事

- 作为公众号作者，我希望把当前笔记一键转换为微信编辑器可粘贴的富 HTML，从而减少手工排版。
- 作为技术写作者，我希望代码块、公式、Mermaid、表格、callout、任务列表和本地图片尽量保留原始表达，从而避免发布前重复修修补补。
- 作为多账号运营者，我希望选择不同公众号账号、封面、摘要和草稿更新方式，从而稳定维护多个发布渠道。
- 作为团队内容维护者，我希望把同一篇文章同步到飞书云文档，从而沉淀可协作和可回看的文档。
- 作为多平台创作者，我希望把文章发送到浏览器发布助手，再由浏览器登录态保存到各平台草稿，从而减少重复搬运。

## 功能范围

范围内能力包括实时预览、富 HTML 复制、微信草稿箱同步、飞书云文档同步、多平台浏览器扩展桥接、本地图片和 GIF 处理、数学公式处理、Mermaid 处理、主题样式、账号设置、素材库封面、摘要和同步后清理。范围外是不在插件内直接托管第三方平台登录态、不替用户自动发布最终文章、不在渲染过程中修改源 Markdown。

## 验收标准

- `npm test` 覆盖核心渲染、路径、清洗、同步和错误处理逻辑。
- `npm run scan:guard` 和 `npm run review:guard` 作为 Obsidian 扫描与发布前质量门禁。
- `TEST.md` 用于常规渲染和微信兼容人工检查，`TEST_MATH.md` 用于公式相关人工检查。
- 修改生成物来源时，`npm run generate:embedded`、`npm run generate:styles` 或对应 check 脚本需要保持输出同步。
- 微信、飞书和浏览器扩展相关改动需要覆盖配置缺失、权限失败、网络失败、重试和用户可读提示。

## 维护规则

- 每次需求边界、用户故事、验收标准发生变化后，必须检查并更新本文件。
