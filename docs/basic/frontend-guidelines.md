# 前端开发规范

## 适用范围

本文件覆盖 Obsidian 插件内的转换器面板、设置页、发布弹窗、预览区、状态提示和样式控制。界面应服务创作者的连续写作与发布流程，优先保持轻量、清晰、可扫描和接近 Obsidian 原生体验。

## 界面结构

- 转换器以实时预览为核心，顶部胶囊切换“文章模式”、“微信贴图”与“图片卡片”视图。
- 设置页和发布弹窗使用 Obsidian 原生控件、Modal、Setting 和简洁 DOM helper，避免脆弱的自定义交互。
- 卡片模式设置收敛在侧边栏设置面板中，采用 `[排版 Token]` 与 `[封面设置]` 双 Tab 分割，不在全局插件设置中混杂笔记专属的卡片尺寸/封面设置：
  - **排版 Token Tab**：调整比例（3:4 / 3:5 / 9:16）、卡片主题（极简白 / 渐变蓝 / 黑金 / 霓虹紫 / 森林绿 / 玫瑰金）、字号、行高、页面内边距、页码开关与水印文本；
  - **封面设置 Tab**：封面开关、版式预设（纯文字排版 / 主题自适应版式 / 全屏意境大图 / 纯海报整页铺满）、主标题、副标题与作者署名。
- 发布弹窗按微信公众号、飞书云文档、其他平台分区，卡片导出使用专属有界导出弹窗（表单区/逐页进度区/失败清单与结果定位区）。
- 样式源文件在 `styles/` 下按职责维护，`styles.css` 作为生成物参与插件打包；`scripts/build-styles.mjs` 中的片段顺序是级联顺序的唯一来源。
- 文章预览、贴图预览、卡片预览（`card-preview.css`）、通用设置面板控件、卡片侧栏设置（`card-settings.css`）、卡片导出弹窗（`card-export.css`、`card-export-progress.css`）与 AI 设置（`ai-settings.css`）分别维护在独立样式片段中，避免把模式专属规则堆回通用文件。
- 删除样式前必须先搜索视图、服务和测试中的类名引用；拆分样式时保持原有选择器顺序，并通过生成物检查与同入口截图确认没有视觉漂移。
- 主题样式由 `themes/apple-theme.js`（文章）与 `services/card-themes.js`（卡片）承接，卡片主题统一对齐六套配色与版式预设。

## 交互规范

- 预览刷新要保持快速、稳定，避免因为单个媒体或公式失败阻塞整篇笔记；卡片编辑输入后通过 300ms 防抖合并调度排版，收到输入事件后 ≤250ms 即时展示更新中标记。
- 单张卡片复制：缩略图右上角提供悬停复制按钮，`stopPropagation` 隔离点击跳原文，纯内存捕获 PNG 写入系统剪贴板，成功/失败均提供清晰 Notice 反馈。
- 批量卡片导出：关闭弹窗不取消后台导出（再次打开顶部导出图标恢复同一任务）；显式点击“取消”立即停止后续任务调度，保留已保存图片；全部成功或用户取消时不落盘无用文件，仅在有失败页时写入 `export-manifest.json`；失败页支持断点重试。
- 移动端隔离：移动端环境下卡片模式展示明确的桌面端提示态，完全阻断排版与 Electron 依赖，保证文章与贴图功能稳定。
- 用户可见错误用自然中文解释当前影响和下一步动作，不暴露不必要的内部模块名、错误码或堆栈。
- 账号、封面、摘要、素材库和输出目录等高影响设置应保留用户明确选择，不隐式覆盖。
- 涉及 HTML 写入、样式、链接、代理 URL、文件清理和动态加载时，优先使用已有安全 helper 和扫描友好写法。

## 维护规则

- 每次新增界面模式、组件规范或交互规则后，必须检查并更新本文件。
