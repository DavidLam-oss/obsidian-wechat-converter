# 前端开发规范

## 适用范围

本文件覆盖 Obsidian 插件内的转换器面板、设置页、发布弹窗、预览区、状态提示和样式控制。界面应服务创作者的连续写作与发布流程，优先保持轻量、清晰、可扫描和接近 Obsidian 原生体验。

## 界面结构

- 转换器以实时预览为核心，左侧/设置区负责控制，右侧预览负责展示最终发布效果。
- 设置页和发布弹窗使用 Obsidian 原生控件、Modal、Setting 和简洁 DOM helper，避免脆弱的自定义交互。
- 发布弹窗按微信公众号、飞书云文档、其他平台分区，不把不同平台的账号、状态和失败恢复混在同一个动作里。
- 样式源文件在 `styles/` 下按职责维护，`styles.css` 作为生成物参与插件打包；`scripts/build-styles.mjs` 中的片段顺序是级联顺序的唯一来源。
- 文章预览、贴图预览、通用设置面板控件、贴图设置和贴图发布弹窗分别维护在独立样式片段中，避免把模式专属规则堆回通用文件。
- 删除样式前必须先搜索视图、服务和测试中的类名引用；拆分样式时保持原有选择器顺序，并通过生成物检查与同入口截图确认没有视觉漂移。
- 主题样式由 `themes/apple-theme.js` 统一接线；主题登记、动态颜色角色和主题专属样式分别拆在 `apple-theme-config.js`、`apple-theme-colors.js` 和专用主题模块中，避免继续堆入主题主类。
- “图文志”是文章输出主题，不改变插件操作 UI。它使用用户选择的主题色或 customColor 派生 `accent / accent-readable / accent-deep / accent-soft`，同时保留高可读中性色；亮色自定义色不能直接承担白底文字。
- 图文志只支持 `hero:` 显式首图增强和默认 regular 图片：`![hero: 图注](image.png)` 的 marker 会在输出中被消费；未标记图片不按尺寸、文件名或位置猜角色；空图注不输出空 `figcaption`。
- 主题输出必须以标签级内联样式为合同，不依赖 `<style>`、class CSS、伪元素、复杂 Grid、动画或固定第二强调色。预览、复制和草稿同步共享同一基础 HTML；自定义 CSS 保持后置覆盖能力。

## 交互规范

- 预览刷新要保持快速、稳定，避免因为单个媒体或公式失败阻塞整篇文章。
- 用户可见错误用自然中文解释当前影响和下一步动作，不暴露不必要的内部模块名、错误码或堆栈。
- 同步类动作需要清楚展示进度、成功状态、失败原因入口和可重试路径。
- 账号、封面、摘要、素材库和输出目录等高影响设置应保留用户明确选择，不隐式覆盖。
- 涉及 HTML 写入、样式、链接、代理 URL、文件清理和动态加载时，优先使用已有安全 helper 和扫描友好写法。

## 维护规则

- 每次新增界面模式、组件规范或交互规则后，必须检查并更新本文件。
