# 前端开发规范

## 适用范围

本文件覆盖 Obsidian 插件内的转换器面板、设置页、发布弹窗、预览区、状态提示和样式控制。界面应服务创作者的连续写作与发布流程，优先保持轻量、清晰、可扫描和接近 Obsidian 原生体验。

## 界面结构

- 转换器以实时预览为核心，左侧/设置区负责控制，右侧预览负责展示最终发布效果。
- 设置页和发布弹窗使用 Obsidian 原生控件、Modal、Setting 和简洁 DOM helper，避免脆弱的自定义交互。
- 发布弹窗按微信公众号、飞书云文档、其他平台分区，不把不同平台的账号、状态和失败恢复混在同一个动作里。
- 样式源文件在 `styles/` 下维护，`styles.css` 作为生成物参与插件打包。
- 主题样式由 `themes/apple-theme.js` 承接，内置 `github`、`wechat`、`serif` 三个 UI 中展示为“简约 / 经典 / 优雅”的预设。

## 交互规范

- 预览刷新要保持快速、稳定，避免因为单个媒体或公式失败阻塞整篇文章。
- 用户可见错误用自然中文解释当前影响和下一步动作，不暴露不必要的内部模块名、错误码或堆栈。
- 同步类动作需要清楚展示进度、成功状态、失败原因入口和可重试路径。
- 账号、封面、摘要、素材库和输出目录等高影响设置应保留用户明确选择，不隐式覆盖。
- 涉及 HTML 写入、样式、链接、代理 URL、文件清理和动态加载时，优先使用已有安全 helper 和扫描友好写法。

## 维护规则

- 每次新增界面模式、组件规范或交互规则后，必须检查并更新本文件。
