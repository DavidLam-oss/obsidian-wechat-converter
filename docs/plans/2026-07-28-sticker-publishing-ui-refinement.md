# 微信贴图发布流程 UI 收敛方案

> 状态：已确认，按本文实施
> 更新日期：2026-07-28
> 来源：基于外部讨论稿 `obsidian-wechat-publish-ui-discussion.md`，结合当前项目代码、测试和微信贴图接口约束复核后重写
> 关联方案：`docs/plans/2026-07-26-sticker-publish-modal-and-content-cleaning-plan.md`

## 1. 目标

让微信贴图流程里的三个界面各司其职：

- 侧栏预览负责确认最终结果，并保留图片排序、移除和恢复能力。
- 发布弹窗负责补齐发布信息、处理图片和阻止无效同步。
- 设置面板只展示真实生效的选项与转换规则。

本次沿用已经确认的「克制工具感」方向。视觉重点是状态清楚、信息可扫、操作就近，记忆点仍是：**看到的图片顺序就是同步到微信草稿后的顺序**。

## 2. 已核实的产品事实

以下事实以当前代码和接口行为为准，优先级高于原讨论稿中的背景假设：

1. 微信贴图不是纯文字消息。公开 `draft/add` 接口要求 `newspic.image_info` 至少包含 1 张图片，最多 20 张。
2. 侧栏不是只读结果页。用户已经可以在这里调整顺序、移除图片、撤销移除和恢复全部，因此这些能力继续保留。
3. 贴图文案不是简单“删除 Markdown”。代码块、表格、公式和脚注会转换成适合纯文本阅读的内容；Frontmatter 等机器标记才会被忽略。
4. 插件只同步到微信公众号草稿箱，不应使用“正式发布”“发布成功”等会让用户误以为内容已经对外发送的措辞。
5. 贴图的排版不会继承文章主题。文章模式与贴图模式可以共享 Obsidian 控件、间距和状态色，但不能暗示文章字体或富文本样式会进入贴图。

## 3. 信息架构

### 3.1 侧栏预览

展示顺序：

1. 发生过复杂结构转换时，显示一条低权重转换提示。
2. 有图片时，显示图片列表、数量、排序/移除/恢复操作和一条简短顺序提示。
3. 没有图片时，不渲染图片区标题、`0 / 20` 徽标和大虚线空框；只显示紧凑的阻断提示。若存在可恢复图片，恢复操作仍紧邻提示显示。
4. 文案区标题使用「发布文案」，副标题使用「将以纯文本同步到微信草稿」。
5. 文案正文采用阅读表面，不模拟输入框，不使用厚重卡片包裹。

### 3.2 发布弹窗

展示顺序：

1. 发布账号。
2. 贴图标题及标题字数。
3. 一行文案字数与转换摘要。
4. 发布图片、图片数量、上传和素材库入口。
5. 图片网格、恢复操作及与图片相关的错误提示。
6. 取消与「同步到贴图草稿」。

不再展示独立的「发布检查」卡片。标题、文案、图片各自在自己的上下文中显示数量和错误，避免同一数字重复出现。

### 3.3 设置面板

贴图模式只保留：

- 配图序号：控制是否在纯文本文案中插入 `[配图 N]`。
- 纯文本转换规则：说明实际转换行为和影响范围。

设置说明不得把“图片排序”写成转换规则，也不得声称代码块和表格被直接删除。

## 4. 状态规则

同一套状态规则供侧栏和发布弹窗使用，避免两处自行判断后逐渐漂移。

| 字段 | 正常 | 接近上限 | 阻断 |
| --- | --- | --- | --- |
| 图片 | 1–19 张 | 20 张，停止继续添加 | 0 张或超过 20 张 |
| 标题 | 1–17 字 | 18–20 字 | 空标题或超过 20 字 |
| 文案 | 0–899 字 | 900–1000 字 | 超过 1000 字 |
| 素材归属 | 均属于当前账号或为本地/正文图片 | 不适用 | 存在其他公众号账号的素材 |

阻断原因按用户修复路径排序：

1. 图片不足或超限。
2. 标题为空或超限。
3. 文案超限。
4. 公众号素材与当前账号不匹配。

按钮保持结果导向：

- 可同步：`同步到贴图草稿`
- 无图片：`图片不足，无法同步`
- 图片超限：`图片超限，无法同步`
- 无标题：`请输入贴图标题`
- 标题超限：`标题超长，无法同步`
- 文案超限：`文案超长，无法同步`
- 素材账号不匹配：`素材账号不符`

## 5. 文案规范

### 5.1 无图片

- 侧栏：`还缺 1 张图片，当前贴图无法同步。请在笔记中插入图片，或在发布弹窗中上传。`
- 发布弹窗：`贴图至少需要 1 张图片。可上传本地图片，或从当前公众号素材库选择。`

图片不是可选项，不使用“可不添加”“如果需要”等表述。

### 5.2 转换说明

- 转换摘要：`已转换为纯文本：代码块 1 处、表格 2 处。笔记原文未改动。`
- 设置标题：`纯文本转换规则`
- 设置正文：
  - `自动忽略 Frontmatter 等机器信息`
  - `代码块、表格、公式和脚注会转换为可读纯文本`
  - `只影响预览和草稿，不会改动笔记原文`

内部仍可暂时沿用 `removed` 数据字段以控制改动范围，但用户界面统一使用“转换”，不使用“删除”“清理掉”。

### 5.3 配图序号

- 设置项：`在文案中插入 [配图 N]`
- 说明：`便于读者对应下方图片；只影响贴图文案。`

## 6. 实现映射

| 位置 | 实施内容 |
| --- | --- |
| `services/sticker-publish-state.js` | 新增纯函数，统一数量状态、阻断原因、按钮文案和转换摘要 |
| `views/publish-modal/sticker-publish-content.js` | 移除独立发布检查卡；接入统一状态；把文案计数、转换摘要和图片错误放回相关区域 |
| `views/converter/sticker-preview.js` | 0 图时收起图片区；保留恢复；更新文案标题、副标题、阅读表面和接近上限状态 |
| `views/converter/settings-panel.js` | 修正配图序号与纯文本转换规则的名称和说明 |
| `styles/preview.css` | 新增紧凑阻断提示、文案副标题和阅读表面；移除侧栏大空框依赖 |
| `styles/wechat-publish.css` | 将发布检查卡样式替换为轻量元信息、转换摘要和上下文错误 |
| `tests/` | 覆盖统一状态模型、0 图侧栏、弹窗信息层级、接近/超过上限和设置文案 |

不在本次范围内：

- 文章模式、飞书或其他发布渠道。
- 微信贴图的数据模型重构。
- 修改 Markdown 清洗算法本身。
- 改变图片上传、素材库、排序或同步 API 行为。
- 把内部 `removed` 字段全局迁移为新字段。

## 7. 验收标准

### 功能

- 0 张图片时，侧栏没有图片标题、数量徽标、大虚线空框或无意义的拖拽提示。
- 0 张图片时，发布弹窗明确说明至少需要 1 张，并保留两个添加入口。
- 图片恢复能力在侧栏和弹窗中都可达。
- 发布弹窗不再出现独立「发布检查」卡。
- 标题、文案、图片计数各只在最相关的位置出现。
- 900–1000 字文案显示提醒态，超过 1000 字显示阻断态。
- 转换摘要使用用户可读标签，不暴露 `codeBlocks`、`tables` 等内部 key。
- 设置面板准确说明 `[配图 N]` 和纯文本转换行为。

### 视觉与可用性

- 保持 Obsidian 原生主题变量、现有按钮与图标体系，不引入新资产。
- 有图时图片网格继续保持侧栏 3 列、弹窗 5/4/3 列响应式规则。
- 文案预览看起来是可阅读结果，不像可编辑输入框。
- 错误靠近对应字段，不靠底部总卡片解释。
- 浅色与深色主题下，正常、提醒和阻断状态均可辨认。

### 验证

- 运行贴图状态纯函数测试。
- 运行贴图预览和发布弹窗 UI 测试。
- 运行 `npm run scan:guard`、`npm run build`、`npm run review:guard`。
- 对修改前后、关键区域和同构槽位生成视觉证据。
