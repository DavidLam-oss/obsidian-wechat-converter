## 新增需求

### 需求：项目级产品与设计上下文文档
基于现有 Obsidian 插件代码与界面事实，新增根目录 PRODUCT.md 和 DESIGN.md，为后续产品、交互与视觉调整提供统一且可复用的依据。

#### 场景：主流程成功
- **当** 维护者或 Agent 在规划产品、交互或视觉改动前读取 PRODUCT.md 与 DESIGN.md
- **则** PRODUCT.md 覆盖用户、产品目的、品牌性格、反例、设计原则和可访问性

#### 场景：边界情况保持可见
- **当** 现有实现与推荐规范不完全一致时，记录为历史现状而不是全部提升为未来标准
- **则** 产品应保持该情况明确可见，以支持实现和验证

#### 场景：失败模式得到处理
- **当** 文档虚构项目事实
- **则** 产品应提供有边界且可评审的结果
