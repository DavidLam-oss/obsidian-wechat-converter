# 设计

## 背景

在继续规划自定义 CSS、高亮、飞书体验和跨仓库授权状态修复前，先建立稳定的产品与设计依据，减少后续方案冲突、遗漏和过度设计。

## 目标

- 建立项目级产品上下文
- 建立项目级视觉与交互规范
- 为后续修复规划提供不冲突、可验证的设计依据

## 范围

- 新增根目录 PRODUCT.md
- 新增根目录 DESIGN.md
- 校验文档结构、设计 token 与仓库事实一致性

## 约束

- 事实来源限于 README、AGENTS.md、docs/basic、styles、themes、views 与现有截图
- 保留当前工作区既有未提交改动
- 不把历史实现中的不一致全部提升为未来标准
- 不记录凭据、授权码、用户数据或云端状态
- 不改变现有安全、隐私和平台职责边界
- Obsidian 原生设计变量与控件
- 项目现有 styles 和 themes 源文件
- impeccable PRODUCT.md 与 DESIGN.md 结构规范
