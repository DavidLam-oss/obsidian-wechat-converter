# 字体与媒体

## 字体决策

1. 字体属于阅读核心，但插件产物预算、移动内存与审核时间也是真实约束。先检查 release 文件字节数和实际加载路径，不能只看源码字体大小。
2. 乔木阅读器默认朱雀仿宋；优先一个许可清楚的离线 WOFF2 字库/常用字集，配系统 serif/sans-serif 与自选设备字体。不要为字体下拉捆绑多套大字体。
3. 子集应有可重复的生成脚本、上游版本/摘要、覆盖范围与 SIL OFL 声明；缺字必须回退到系统字体，不能暗示全字库覆盖。Latin、标点、繁简与罕见人名都要抽查。
4. Base64 有体积膨胀，gzip 源码在 JS 中不等于安装包变小；最终测 main.js/styles.css。RSS 的 5 MB 预算与约 2.61 MB WOFF2 是 2026-09-07 案例，不是写死的官方政策。
5. 字体名可由用户输入；不要承诺所有手机能枚举或授权读取系统字体。正确引用/转义 CSS family 值。前后台共用字体状态，加载失败回退，不重建文章 DOM、不重置滚动。

## 图片

远程图片要真的显示：验证请求、MIME、正文/缩略图、缓存命中与离线重开。限制响应大小、总缓存、并发与过期清理；不要把私人源 URL 写到日志。普通订阅直接读取其源，不擅自上传代理或 AI。

拖拽到编辑器后需生成图片嵌入而非普通附件链接。用宿主确定附件位置（核实当前 SDK 的 getAvailablePathForAttachment 等能力），避免覆盖同名文件；保存二进制后使用正确的 Markdown embed。源文件名/路径需转义或由宿主生成链接。

选中文字与拖图片是不同交互，不让图片拖动破坏文本长按选择。RSS 与本地 Markdown 图片分别测；失败不能插入看似成功的文件名。合成 drop、真实桌面拖放与移动系统手势三种证据分别记录。

## 字体与对象级外观

系统字体可减小包体，但跨设备是否存在不同；保存稳定字体标识并提供回退，不声称每个平台都能用同一字体。每本书的外观与新书默认分层：对象覆盖 → 全局默认 → 安全值；“设为默认”不应改掉其他书的覆盖。重排前后保持阅读位置，并在不同格式分别验证。
