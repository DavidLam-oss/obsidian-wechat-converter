# 产品界面与设置

## 主任务优先

- 先写出插件的核心动词和对象，再设计入口：执行命令、编辑文本、浏览/管理数据、导入导出、同步外部服务、播放媒体等需要不同界面，不套用 Reader/RSS 的双栏或频道结构。
- 第一屏展示完成主任务所需的状态、目标和动作；历史、诊断、路径、协议和高级筛选渐进展开。空态、禁用态和错误态提供下一步，不用长篇说明替代可操作入口。
- 保持 Obsidian 原生页签、命令、菜单、设置和键盘模型。插件拥有的 UI 才能定制；不要为做“沉浸感”全局隐藏宿主导航或改变其他插件布局。
- 列表、树、表格、日历、画布和编辑器分别验证真实密度、滚动、键盘和窄屏；桌面 hover 不能成为移动端唯一入口。

## 阅读优先

仅用于 RSS、电子书、PDF、长文阅读等内容消费插件。

- 工具栏紧凑，字体和摘录等操作放在同一功能区域；上一篇/下一篇保留导航含义。标题上方重复来源、日期、版本提示若无决策价值可移除。
- 列表保持信息密度：来源/日期弱化，标题清楚，摘要截断，有图则显示合适缩略图；列表宽度可拖拽、可收起，阅读正文保留合理版心。
- 颜色优先兼容宿主，必要时使用插件作用域语义变量提供独立、克制的选中态。不能只换背景而忽视标题、摘要、hover、focus、暗色对比。
- Lucide 等成熟图标优先，语义准确；树代表乔木，未读不强行用邮箱。商店自定义图标能力先核实，不承诺上传 PNG。

## 频道与搜索

桌面菜单锚定触发器；手机使用适合触摸的底部面板或原生选择流程，别把桌面 hover 菜单缩小。频道按聚合、订阅分组、来源组织，有图标/缩写，长列表可搜索。搜索有清晰 x；清除后保留输入焦点，空值隐藏按钮。

每频道记住列表滚动、当前文章、正文位置、筛选和搜索。重复选择当前频道只收起菜单。文章切换立即响应，慢内容在正文局部加载；取消或丢弃过期响应。J/K 等仅在阅读上下文生效，不截获输入框、编辑器、IME 或带修饰键输入。

## 设置

设置页具体布局、黑灰控件、渐进表单、关于页和多窗口验收，按 [设置 GUI](settings-gui.md) 执行。

以最低操作成本和认知负担组织配置。默认只显示当前任务所需的选择、必要输入和可用状态；少量类型优先平铺选择，复杂模型或服务商用可搜索弹窗；简单有限值按空间选合适的原生控件。沿用已有账号和合理默认值。路径、协议、安装命令、提示词、同步细节及维护操作默认折叠，遇到阻塞时显示具体下一步并引导展开相应项。未安装、未登录、缺密钥等问题不能隐藏，也不能声称“选好即可用”而未经验证。常见操作用成熟图标和简短可见标签，不用装饰图片或大段技术说明代替交互。

使用当前 SDK 支持的原生 Setting/设置接口；按用户任务命名分组，不照搬所有项目的 tab 数。先审计每个设置是否真实生效、是否重复、是否值得由用户决定：无效项修复或移除，低频项折叠。标题、说明、设置行共用明确的对齐基线；长标题和窄窗口下导航仍应清晰。反复切换 tab 验证只有一条导航；宿主复用节点时清理自建内容，监听不要重复注册。

前台字体面板与后台共用状态，即改即保存；点击外部关闭，不加完成/保存或无需求的恢复默认按钮。面板靠近锚点并限制视口，正文滚动不把它甩出屏幕。失败保留最后有效设置并反馈。

关于：版本、更新记录、帮助、GitHub Issues、作者的公开主页。更新说明按版本展示，避免每次打开都弹公告。插件升级走宿主机制，不自更新可执行文件。普通用户不需要后端服务地址、内部 IDs 和调试开关。

## 设计判断与宿主边界

用户明确不喜欢左侧装饰竖线：卡片、引用、callout、列表、页签、按钮和筛选项都不要用它表达层级、强调或选中态。包括 `border-left`、`border-inline-start`、单侧 inset `box-shadow` 和伪元素画线。优先使用整体浅色背景、完整细描边、字重或勾选图标，并保留清晰的 `focus-visible` 与可访问状态。这是用户视觉偏好，不是 Obsidian 官方规范，也不要求移除功能性分隔线或文档语义。

用户要求向其他产品学习时，查看当前官方帮助或真实产品界面，提取支持本产品任务的机制；不照抄配色、功能数量或社交/商店结构。将依据、设计推断与用户明确偏好区分，不能把“最佳实践”当成无需验证的理由。

样式只作用于插件拥有的视图。正文背景应覆盖完整阅读画布及留白；工具栏使用独立、克制的宿主兼容表面。去掉重复插件标题，不隐藏 Obsidian 的全局页签、侧栏或调整整个应用宽度。检查分屏、侧栏开关、独立窗口与深浅主题，不能为修空白而破坏宿主布局。

长模型名、路径、来源名等标识在紧凑列表中省略，在详情中允许完整换行；状态和主要动作不能被挤出。对播放器等单任务插件，主视图应以当前媒体、核心控制和恢复状态为中心，目录/分类/历史渐进展开；主题切换若存在，应切换完整可操作的体验，不只是换色。此判断只适用于媒体/单任务产品，不要求普通工具隐藏宿主信息。

## 无障碍与触摸

默认不用 `title`、`setTooltip`、`aria-label` 生成的悬浮说明。2026-09-14 反编译 Obsidian 客户端核实：任何带 `aria-label` 的元素在指针移入时都会弹出提示气泡，与是否调用 `setTooltip` 无关；只清空 `title` 或只改 `data-tooltip` 都拦不住它。正确做法是不给插件元素加 `aria-label`。必要可访问名称仍必须有：图标按钮使用 visually-hidden 子文本或 `aria-labelledby`，表单输入使用原生 `label`。发布前跑 `python3 scripts/audit_release.py <plugin> --scan-tips`，再真实 hover 验证不能出现未要求的 tips。保留 focus-visible、Escape、键盘遍历和合理触摸区域。仅当用户明确要求或含义仍不可辨识时为单个控件保留 tooltip，不能只复述可见文字；例外不扩展到全产品。禁止全局隐藏宿主 tooltip；动态控件和独立窗口也要验证，相关监听随窗口和插件卸载清理。

移动端保留系统长按选区手柄；不要在 touchstart 全面 preventDefault，不要把整个正文 draggable。处理 selectionchange 与工具点击不丢选区；工具浮层不遮挡选择。窄屏截图只能证明布局，不能证明 iOS 原生选区、拖放、键盘。

## 空态

没有选文章时提供安静的阅读入口：一句主文案、一则可切换的功能场景、少量快捷键。不要铺大灰卡、密集说明或随机刷新内容。只有来源切换或用户点下一则时更换，重渲染保持稳定。空列表、搜索无结果、无正文、加载与错误是不同状态。

## 最新偏好优先

2026-09-26 Agent 明确要求仅纯图标保留 tips，文字按钮和输入去掉重复说明。该项目例外优先于默认不用 tooltip；其他项目按当前明确选择。关于二维码是否默认展开同样按项目最新要求。不要用旧会话的统一规则抵消新的用户纠正。
