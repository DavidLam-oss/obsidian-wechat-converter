# 数据、同步与异步可靠性

按风险使用，不给只读插件引入迁移框架。官方 API 规则与本技能建议分开标记。

## 文件读写决策

| 场景 | 做法 | 必测失败路径 |
| --- | --- | --- |
| 展示笔记 | cachedRead，允许宿主缓存 | 外部文件变更后刷新 |
| 编辑当前笔记 | Editor 的范围修改/事务 | 撤销、选区、未保存编辑 |
| 后台修改既有文本 | Vault.process，同步回调 | 两个写入者同时追加 |
| AI/联网处理后替换 | 先取快照、异步处理，提交时检查当前内容 | 等待期间用户改字，不覆盖新内容 |
| 修改属性 | processFrontMatter | 非目标属性保留、空属性 |
| 重命名或删除 | FileManager.renameFile / trashFile | 链接更新、用户垃圾箱偏好 |

`process` 回调不能 async。若结果基于过期快照，重新计算或提供冲突处理；不能把旧全文硬写回。单次文件操作的原子性不代表多文件事务，更不代表跨设备同步锁。[官方 Vault](https://docs.obsidian.md/Plugins/Vault)。

## 配置迁移：本技能建议

1. 默认值与持久化数据分离；加载后检查类型、范围、枚举，嵌套结构不能只靠浅层 Object.assign。
2. 需要迁移时用 schemaVersion 和连续迁移步骤；相同步骤重复执行结果一致，成功持久化后才标记完成。
3. 迁移仅修改拥有的字段。降级遇到更高 schema 时不要用旧默认值覆盖；非兼容数据保留并报告。
4. 大规模或不可逆迁移先保留可恢复副本；磁盘写入失败时不报告成功、不先删除旧数据。备份限制范围与数量，避免复制全部 vault 或密钥。
5. 连续设置变更要有明确写入顺序，可合并中间状态；不允许较早请求迟到后覆盖新值。失败应可见并支持重试，不假定关闭窗口等于保存完成。
6. 可重建缓存、用户设置、用户笔记分开管理。缓存损坏可重建；不能对 loadData 的任意错误都清空用户配置。

验证：旧配置、缺字段、错误类型、重复迁移、未来 schema、写入失败、快速连改后重开。只有涉及迁移时才运行全部案例。

## 索引与同步：本技能建议

- 本地阅读源只遍历用户指定范围。缓存键包含来源与稳定身份；mtime/size 可作快捷线索，不是永远可靠的内容哈希。
- 启动历史扫描与实时新增分开。Obsidian 初始化会为旧文件触发 create；只处理真正新增时等待布局完成或检查 layoutReady。[官方启动优化](https://docs.obsidian.md/plugins/guides/load-time)。
- 自己写入引发的 modify 事件要能收敛：比较目标内容、只写有差异的数据；不用全局“忽略下一次事件”吞掉其他写入者。
- create/modify/rename/delete 按文件更新，合并突发事件。删除和重命名同时清掉旧路径缓存、搜索结果与选中引用。
- 插件暂停、设备恢复或索引版本变化后按需重验。两个设备同步 data.json 不是数据库事务；不要承诺 settings 自动无冲突合并。

## 请求与队列：本技能建议

- 每个任务绑定来源、目标文件与请求代次；开始时捕获目标，完成时再次校验，不临时取“当前活跃笔记”。
- 有界并发与缓存，不对全库/所有图片无上限 Promise.all。卸载后阻止迟到回调更新 UI 或写文件。
- 区分可重试的网络/服务错误、认证失败和用户取消。重试有上限与退避；写入/收费调用没有幂等保障时不自动重复。
- UI 超时或丢弃结果不等于底层请求取消；仅使用当前 requestUrl 类型真正支持的能力。日志剔除认证头、完整私人 URL 和笔记正文。
- 用户明确选择的资源（文章、电台、书籍、模型）失败时，默认停留在该选择并给出恢复动作；不要悄悄遍历整条队列。自动续播/回退只有在产品明确承诺时启用，也必须有失败上限。
- 重复点击同一目标要去重。每次尝试带独立代次、timer 和取消状态；暂停、切换、卸载或新请求到来时取消旧恢复任务。用户取消、旧请求被替代、媒体/网络真实错误分别处理，不能让旧 `play()`/fetch rejection 污染新选择。
- 重试延迟、连接超时和“认定失败”的条件是不同概念；按真实协议与用户体验设定有界策略，不能把短暂 fallback delay 误报为完整连接超时。

## 密钥

官方 SDK 将 SecretStorage 标为 1.11.4 起可用；最低宿主与项目类型匹配时，设置只存 secret 名称，SecretComponent 提供选择，使用时读取值并处理 null。旧宿主需明确兼容路径，不能静默退回明文。不要读取/清理用户未选择的其他 secret。

官方说明 secret 位于按 vault 区分的 local storage，可被其他插件按名称使用；不要声称它是 OS Keychain、端到端同步或插件隔离沙箱。迁移已有明文凭据应成功写入并验证后才移除旧字段，不输出值。

来源：[Store secrets](https://docs.obsidian.md/plugins/guides/secret-storage)、[SDK 类型](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)。API 版本要在实施时复核。

## 默认值、个人数据与跨日迁移

新安装预设与升级迁移分开。用幂等标记控制一次性补充，不在每次升级恢复用户已删除的入口/页签。社区精选目录、全部可发现目录、个人订阅分别建模；用户添加、OPML 导入、文件夹添加均归个人所有，不能因共享后台自动广播给其他用户。

日记写入优先读取核心插件当前运行配置，必要时才回退磁盘配置；目录、日期格式、模板共同参与创建。跨文件待办结转需处理目标已写、源未更新等中断，用持久日志、稳定身份或可验证的恢复步骤避免重复；不把迁移标成“已完成任务”。全文修改前重新读取当前内容，防止覆盖用户或同步产生的新编辑。
