# 规模、虚拟化与资源生命周期

用于大型 PDF/媒体、超长笔记、大型任务板/日历、全库索引、图片密集视图，以及“启动慢、输入卡、内存持续增长或越用越慢”的问题。先按插件类型选择启动、交互延迟、吞吐、DOM、内存、网络或包体指标；不把数据量、单次峰值或按钮暂时无响应直接叫做内存泄漏。

## 先找保留链

- 分开检查原始数据、解析模型、索引/缓存、列表或页面 DOM、canvas/图片、Blob URL、监听器和异步任务。输入数据较小不代表大内存一定由原始字节造成；任务/日历插件也可能因全量 DOM 或事件保留放大资源。
- 记录“打开 → 初始渲染 → 滚动/跳页/搜索 → 关闭文档 → 卸载插件”的时间线，观察多轮后的趋势与关闭后的回落。Heap、DOM 节点数、canvas 像素、进程 RSS 是不同指标。
- Obsidian/Electron 的进程 RSS 可能包含宿主页面、其他视图、插件、GPU 或子进程。未做进程/插件隔离时，只能报告环境总量或上界，不能宣称是插件独占内存。

## 规模化默认模式

- 不为所有页、记录、日期格、任务或搜索结果预先创建完整 DOM。保留轻量模型/索引，仅为当前视口和有限邻近区域创建昂贵交互层；离开窗口后释放并允许按需重建。
- 搜索、跳页、批注和 AI 上下文需要稳定的文档级索引或轻量文本数据，但不等于必须永久保留每页的定位 span。把“可检索数据”和“可交互渲染层”分开设计。
- 销毁路径要覆盖文档切换、视图关闭、插件卸载、请求取消和渲染失败。释放 observer/listener、timer、Blob URL、canvas、渲染任务及库支持的页缓存；迟到任务不得重新挂回已关闭视图。
- 虚拟窗口大小由实际滚动、跳页、搜索和设备内存测量决定，不把一次项目里的页数或 screenful 数写成通用常量。

## 稳定版保护

性能修复可能改变渲染时序、搜索、选区和批注锚点。若稳定版本已发布，先从该发布基线建立修复分支，只做定位到根因的最小变化；不要从含未验证重构的 ahead-of-release 树直接发补丁。实现通过后仍按正常发布门禁处理。

## 验收矩阵

至少选择一份能复现问题的规模数据和一份普通规模数据；fixture 可以是文件、笔记集合、任务/事件集、远端分页数据或媒体队列：

- 大文件：打开峰值与稳定区间、滚动、连续跳页、远距离跳转、搜索、选区/复制、批注或项目实际依赖的文本能力、关闭后的 DOM/资源回收。
- 普通文件：首屏速度、清晰度、搜索、选区、高亮、页码/位置恢复，防止虚拟化优化破坏常见场景。
- 重复性：同一文件多轮打开/关闭、不同文件交替、快速切换时无旧渲染覆盖。
- 证据：记录 fixture 特征、Obsidian 与插件版本、独立 profile/vault、采样方法和无法隔离的进程。自动测试通过与真实宿主大文件结果分开报告。

如果临时 vault/profile 未被启动器识别，先修正隔离环境或只重启该隔离测试进程；受阻的运行不是 live QA。不要关闭用户日常 Obsidian 或其他未保存工作来换取测试环境。
