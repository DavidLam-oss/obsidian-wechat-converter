# 外部集成、跨插件协议与能力

用于第三方 API、同步/发布、跨插件协议、CLI、AI provider、MCP/Skill 和会修改笔记或外部系统的能力。此处约束权限、职责、状态与可验证性；不要求本地单插件引入任何外部集成。

## 集成职责

- 让最接近数据或副作用的模块拥有它：来源插件拥有来源身份/定位，任务插件拥有任务写入，同步适配器拥有远端游标，通用 AI 层拥有 provider/会话/工具。不要在每个功能面复制认证、重试或权限体系。
- 集成使用公开、版本化的小接口：稳定身份、操作意图、不可变输入快照、来源/目标定位、结果和错误。调用方检测接口是否存在并提供降级；不能依赖调试全局、私有 DOM 或开发机器路径。
- 预览、选中或浏览只更新本地待执行状态，不自动产生写入、发布、模型调用或其他外部副作用。用户提交时冻结输入；之后的 UI 选择不能改变已发出的操作。高风险动作显示目标并允许取消或复核。
- 修改兄弟插件或建立双向协议是独立写入范围；当前任务若只授权一个仓库，先给接口方案并报告另一侧尚未实现，不能越界改项目后宣称集成完成。

## 能力最小化

- 普通对话默认不加载外部能力。只在用户明确选择或请求时，为当前轮启用完成任务所需的精确 Skill/MCP/tool；能力名称、作用范围、网络/上传/写入/付费影响在执行前可见。
- 区分“已发现、已安装、已启用、当前轮已授权、执行成功”。不要把能力列表、picker 打开/关闭或一次工具调用事件当成最终结果。
- 插件不得自动安装/更新自身、依赖、Skills、MCP 或其他扩展，也不得下载并执行远程代码。可以检测已安装状态，提供复制命令/安装说明和重新检测；真正安装由用户或宿主管理。
- 写笔记必须显示目标与变更预览，提交前重查原位置/原内容，遇到并发编辑拒绝覆盖或进入冲突处理。读、写、发布、Shell 和任意文件访问不是一个权限等级。

## 服务与结果验证

- 查看连接详情不能顺便测试、启动或切换 provider；“使用此连接”应是显式动作。预设可填默认地址/模型并折叠高级项，但缺密钥、未登录或测试失败必须显示。
- 每个服务、端点、账号/认证、能力与平台路径分别验证。一个真实连接成功只证明该组合；preset、mock、接口样例或测试环境不能外推为其他服务、权限或生产路径已可用。
- 端到端验收包括实际请求、流式/取消、错误恢复、上下文引用和真实输出呈现。`no text returned` 不必然代表无结果：检查协议事件是否返回图片、文件、结构化项或 `savedPath`，并验证插件已渲染、持久化或安全导入对应产物。
- 长模型/连接/能力 ID 在列表中应省略但保留辨识信息，在详情页完整换行；不要让状态徽标、操作按钮或窄屏布局被不可断行标识挤坏。

## 证据合同

分别记录：接口存在、UI 可选择、授权发生、真实工具/provider 调用、输出渲染/写入、取消/失败恢复、重载后状态。未捕获最终结果、仅看到 changed-file 数、或 picker 未选择，都只能报告“进行中/部分观察”，不能写“能力已验证”。

## 近期能力边界

本机 CLI、Node 运行时、ACP/RPC 适配器、账号、模型能力分别检测与报错；缺适配器可否回退须按该工具验证，不能把“CLI 已安装”视为已连通。用户在本地调整菜单可见性不应改写 CLI 的全局模型设置。

从执行事件到最终 UI 必须保留真实结果：图片生成步骤完成不等于图片显示，应解析媒体消息、保存到库内稳定路径、持久化附件并冷启动验证；内部路径不作为正文展示。带 reasoning 的模型可能共享输出预算，按实际提供商文档配置，不能照搬一个固定 max_tokens 到所有模式。

发布集成区分本地预览、服务端接受、草稿 ID、回读正文和正式发表；一种 Bridge 路径成功不证明另一个公开中转 onboarding 正常。401 时保留用户配置，显示可执行的下一步；经核实的缓存信息须区分实时状态。不要因日志中有访问错误就断言它是用户这次操作的根因。
