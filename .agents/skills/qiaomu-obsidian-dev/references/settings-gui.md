# 设置 GUI：乔木默认与验收

适用于乔木 Obsidian 插件自己的设置、弹窗、配置卡片与工具栏。依据见 [近期会话复盘](../reports/retrospective-2026-09-16-to-27.md)。以下视觉约定是用户偏好，不是 Obsidian 官方政策；当前项目明确选择优先。

## 先定信息架构

1. 列出用户要完成的 3–5 个动作，再分组。模型接入按「本机 Agent / API 服务」分，主页配置按「主页 / 外观 / 记录 / 关于」分；不要机械复制四个 tab。
2. 首屏放可用状态与下一步：已连接服务、添加入口、最常用开关。路径、协议、模型参数、维护动作折叠或进入详情。
3. 新手只填必要信息。先选类型/来源，再出现对应表单；切换选项保留各自未提交草稿。密钥来源不确定时让用户选择，不把前缀猜测当可靠识别。
4. 空态直接引导首次添加，成功后回到新条目；失败保留输入、说明具体问题并提供重试。已发现、已配置、已登录、可调用是不同状态。
5. 同一设置只保留一个状态源。前台弹层和后台设置互相同步，普通可逆偏好即时保存；不要每次输入重建整个表单，导致失焦、光标跳动或中文输入中断。

## 控件选择与渐进展开

| 情况 | 优先交互 | 避免 |
| --- | --- | --- |
| 2–4 个互斥类型 | 平铺图标＋短标签；选中后出现字段 | 把关键选择藏进下拉 |
| 多个复杂服务商或对象 | 可搜索选择弹窗，选中后进入详情 | 无尽下拉或首页堆全部参数 |
| 简单有限值 | 清晰的原生选择、分段或单选，按空间决定 | 为“不要下拉”把所有小设置都做成弹窗 |
| 进阶选项 | 行尾 chevron 展开，方向和 expanded 状态同步 | 边框套边框、展开后字段无层级 |
| 添加同类内容 | 统一用「添加」；确需分组再让用户命名 | 内部实现术语「新建分组」代替用户动作 |
| 日常使用与布局管理 | 一个齿轮进入布置状态，随后显示「添加内容」、手柄和完成动作 | 常态同时放多个含义不明的图标 |
| 高频明确动作 | Lucide 图标；陌生或关键动作加短标签 | 用四宫格等含糊符号让用户猜 |

图标简洁不等于所有文字都删除。「添加内容」这种首次使用难猜的动作，在布置状态保留可见文字。按钮提供辅助技术名称；提示气泡遵循项目最新选择，见下文。

## 黑白灰、对齐与留白

- 乔木新组件默认参考 Vercel 的中性黑白灰：浅色下深色主按钮，深色下浅色主按钮；次级操作用弱背景和细边框。不要直接继承紫色 accent 到所有开关、滑块和选中态。危险、错误、成功状态仍保留必要语义区别。
- 只在插件根节点和自己的 Modal/Suggest 根节点设置语义变量；审查 toggle、CTA、slider、checkbox、radio、tab、选中图标、链接、焦点等完整状态。禁止改整个 Obsidian 的主题色。
- 背景卡片必须有真实内边距，文字和控件离边缘一致。桌面可从纵向 16px、横向 18px 起步，窄屏可从 14px 起步；这些是 Home 验证过的起点，不是所有插件固定尺寸。
- 先消除顶部空洞、重复标题和嵌套背景，再微调密度。卡片之间与分组之间使用可辨识的两档间距，不靠大段说明制造层级。
- Logo 使用固定尺寸 flex 容器，与标题垂直居中；清除原生 Setting heading 自带的外边距后再测。不要只凭图标文件边界对齐，核对渲染后的视觉中心。
- 设置标题优先 `new Setting(...).setName(...).setHeading()` 等当前 SDK 支持的接口。样式问题用插件 CSS 解决，不能为方便布局绕过扫描要求。
- 不使用左侧装饰竖线、双重描边、厚重黑框或发光焦点。hover 不改变尺寸；focus-visible 保留轻且可见的轮廓，不能用 outline:none 一删了之。
- 不让「精致」牺牲可读性：检查浅深主题、照片背景、禁用态、长中文/英文、窄窗和 200% 缩放，文字、图标与控件需有足够对比。

## 图标提示与关于页

- 默认移除复述文字的 tooltip，输入框与带字按钮尤其如此。可访问名称仍需保留，使用隐藏文字、原生 label 或 aria-labelledby。
- Agent 在 2026-09-26 明确允许纯图标保留 tips；这是该项目的明确例外，不扩散成所有乔木插件默认开启，也不能被技能默认值再次删掉。核对当前宿主是否将 aria-label 渲染为气泡。
- 关于页先放版本、更新记录、帮助和问题反馈；关注与打赏放后面，公开链接再分次级层。二维码按需展开或直接展示取决于本项目最新要求，不能把某次偏好写成永久统一要求。
- 反馈入口指向对应仓库 Issues；仅使用已确认的公开作者资料。技术地址、内部 ID、诊断日志不放普通用户首屏。外链图片须披露按需请求来源。

## 多窗口与真实验收

- 设置窗口可能是独立 document。使用 `containerEl.ownerDocument`、对应 `defaultView`、所在窗口的事件和生命周期；主 document 查不到节点不等于设置未渲染。
- 检查所有 tab，而不是只修截图里的一行。多次切换后标题和导航各一份；关闭重开和重载后状态保持。
- 至少实际检查：logo/标题中心、卡片四边 padding、主次文字、开关启用/禁用、输入 focus、CTA、选中图标、长路径折行、下拉/弹窗遮挡、滚动条和窄屏。
- 小范围 CSS 改动用真实宿主截图和 computed style 验证即可，不必写镜像实现的单测。配置迁移、异步保存和写入副作用用有意义的回归测试。
- Home 本次参考证据：四个 tab 的行内边距均为 16px 18px；logo/标题中心相同；浅色开关 rgb(32,32,32)，深色 rgb(237,237,237)。数值证明当前实现，不代表所有主题/设备均通过。

## 布局与模块补充

卡片/页签拖动只在布置状态显示手柄，拖动有插入位置、稳定占位、边缘滚动和取消路径；菜单前移/后移作为键盘与触摸备选。实际验证顺序保存、重载、跨页移动与旧异步响应隔离。

默认内容克制，列表默认 3 条可作为主页型插件起点。升级保留旧布局和用户删除的默认项；可选推荐不要悄悄插入旧页面。推荐模块提供用途、适合人群、详情入口，不自动安装，更不能把下载量叫质量排名。
