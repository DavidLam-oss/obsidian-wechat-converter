# Obsidian 插件开发一周复盘 · 2026-09-08—15

范围：Qiaomu Reader、Qiaomu AI RSS、Qiaomu Seed、Qiaomu Radio 的开发、诊断、真实 Obsidian QA 与发布对话。只沉淀跨项目仍有价值的决策；产品专属视觉、临时版本号、个人 vault 路径和未完成尝试不进入通用规则。

> 2026-09-15 纠正：这些项目只作为案例证据，不能成为其他插件的默认产品形状。通用入口改为 `references/plugin-architecture.md`，先区分命令/自动化、编辑器增强、自定义视图、数据索引、导入导出、网络同步、媒体阅读和 AI/Agent，再映射下面发现的问题模式。

| 案例中观察到的现象 | 通用工程模式 | 可适用的其他插件 |
| --- | --- | --- |
| 全页 PDF 文本层造成资源放大 | 数据模型、索引、视口渲染和可回收资源分层 | 日历、任务板、数据库、图库、全文搜索 |
| Reader 测错 vault/格式 | 验证证据绑定构建与宿主身份，主路径不可由相邻路径代证 | 任意插件 |
| Seed 能发现能力但无最终产物 | 外部集成分发现、授权、执行、结果、恢复阶段 | 同步、发布、剪藏、翻译、云服务 |
| RSS 与 Seed 职责重叠 | 用最小版本化协议划分数据和副作用所有权 | 日历+任务、数据库+图表、多插件工作流 |
| Radio 旧请求触发连续跳台 | 任务代次、取消语义、有界恢复、保持当前用户意图 | 搜索、同步、批处理、模型切换、导入 |
| 分类接口非空但语义错误 | 验收最终内容和用户结果，不只验 API/DOM 存在 | 搜索、推荐、解析、导入、AI 输出 |

## 1. 证据身份比“跑过测试”更重要

Reader 测试曾遇到测试 vault 属于另一个 checkout、PDF 扩展被其他插件注册、EPUB 已显示但 PDF 路径仍受阻。结论：真实宿主证据必须绑定 checkout/commit、产物、安装目录、vault/profile、插件版本、宿主版本和 fixture；格式与设备不能互相代证。

纳入：`testing-troubleshooting.md` 的证据身份、冲突隔离和格式 fixture 规则。

## 2. 大文件性能的根因常在交互层，不在文件字节

Reader 大 PDF 案例从约 45 MB 文件追到“为全部页面创建 PDF.js 文本层 DOM”。可复用策略是把轻量搜索/定位数据与昂贵可交互层分离，只渲染视口邻域并在离开后回收。稳定版受影响时，从已发布 baseline 做最小修复，并同时回归代表性大文件与普通文件。

测量必须说明 Obsidian/Electron 进程边界；混合 RSS、其他页面、GPU/子进程或测试采集等待不能包装成插件独占内存和启动时间。自动测试和结构基准不能替代真实文件、关闭回落和多轮趋势。

纳入：新增 `performance-large-files.md`。

## 3. 跨插件集成应是上下文契约

RSS、Reader 和 Seed 的讨论反复显示：内容插件应保留阅读与来源定位，通用 AI 层集中 provider、会话、工具和写回。来源插件传递标题、稳定身份、选区优先的文本快照和回跳链接；选文只更新待发送上下文，不自动调用模型，提交时冻结快照。

兄弟仓库改动不是当前仓库任务的隐含权限。只改一侧时，应交付公开接口与降级方案，并把另一侧标为未实现。

纳入：新增 `ai-integrations.md`。

## 4. “能发现能力”不等于“能力可用”

Seed 的 MCP/Skill/image generation 对话出现过 picker 关闭但未选择、调用没有文本、修改文件但无构建结果、能力可列出但未捕获最终产物。可复用证据链是：发现 → 安装 → 启用 → 本轮授权 → 调用 → 结果事件 → UI 呈现/安全导入 → 失败恢复。

普通对话不全局加载能力；用户明确请求后只加载当前轮所需的精确 Skill/MCP。插件不自动安装/更新扩展或执行远程代码。一个 provider+模型+真实 key 成功不能外推到所有 preset；mock 也不能替代真实认证和结果呈现。无文本时检查图片、文件、结构化项和保存路径，而不是直接把请求判失败或成功。

纳入：`ai-integrations.md` 和测试诊断的 provider 证据规则。

## 5. 用户选择优先于自动恢复

Radio 连续跳台问题由重复点击、旧恢复 timer、主动 pause/load 中断被当作真实错误以及无失败上限共同造成。通用模式是同目标去重、每次请求有代次与取消状态、旧任务不得污染新选择、用户取消与真实错误分开、有限重试后停在当前目标并解释。自动遍历队列必须是明确产品承诺且仍有上限。

纳入：`data-reliability.md` 的请求与队列规则。

## 6. UI 完成度来自主任务与边界状态

本周重复确认：阅读器把正文和“读—摘—记—回”作为主表面；媒体插件把当前播放与核心控制作为主表面；高级设置、目录、分类、历史按需展开。长模型 ID 在列表省略、详情完整换行。外部分类结果不仅要加载成功，还要抽查语义准确性。

tooltip、触摸热区、阅读画布、选区与设置的既有规则已充分覆盖，本次不重复扩写。

纳入：`product-ux.md` 与 `testing-troubleshooting.md`。

## 7. 发布规则得到再次验证，但不重复增加

本周 Reader/Radio 继续证明本地测试、CI、GitHub Release、Preview Scan、正式扫描、目录版本、匿名资产和客户端安装是不同证据。现有 `release.md` 已包含最终 SHA、草稿安装、匿名资产先于默认分支 manifest、正式读回等门禁，因此本轮只记录证据，不再复制同一规则。
